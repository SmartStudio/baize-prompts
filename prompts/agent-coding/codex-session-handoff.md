## 用途

- 目标：把过长的 Codex 会话安全迁移到新会话，不丢现场、不重做已完成工作。
- 约束：不写密钥；不执行 reset / clean / 覆盖现有代码；未提交修改必须安全保留；新会话不复制旧上下文全文；无法自动新建/命名/置顶时须如实说明；禁止重做已完成工作；禁止重问已确认信息；如实汇报测试与构建结果。
- 输出格式：`.codex/SESSION_HANDOFF.md`（仓库 / git 状态 / 代码改动 / 已完成与未完成任务 / 关键决策 / 风险 / 测试结果）；新会话名 `【项目名｜续开发｜阶段 2】`；降级时输出一段可直接粘贴的启动提示词。

## 何时不用

缺目标/约束/格式时不要用；图视频任务不要用；未签边界不要放大自动化。

## 边界

人必须批准：是否入库到生产工作流、是否写入真实仓库/会话。评测 fixture 不得指向真实 vault 或生产密钥。

## 原文

```
当前 Codex 会话上下文过长，请执行一次安全迁移：

先暂停开发，检查当前仓库、Git 状态、代码改动、已完成与未完成任务、关键决策、问题风险和测试结果，并整理到 .codex/SESSION_HANDOFF.md。不要写入密钥，不要执行 reset、clean 或覆盖现有代码，确保未提交修改安全保留。

然后创建一个全新的 Codex 会话，不要复制旧会话全部上下文。新会话命名为：

【项目名｜续开发｜阶段 2】

并将其置顶。若无法自动新建、命名或置顶，请如实说明，并输出一段可直接粘贴到新会话的启动提示词。

新会话启动后，先读取交接文件、AGENTS.md、README.md，检查 git status 和当前代码现场，确认无误后直接从最高优先级的未完成任务继续开发。

不要重复已完成的工作，不要重新询问已经确认的信息，并如实汇报测试、构建和验证结果。
```
