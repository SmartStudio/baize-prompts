# 四道闸：先让人看懂，再谈出厂

一条 Prompt 值不值得收，先看问题和输入，再看原文 Prompt，最后看同一输入的 A/B。没跑过，不出厂。

## 读者先看什么

正文固定走这条路：原始问题 → 给模型的输入 → 复制这条 Prompt → 跑完会差在哪 → 什么时候别用 → 人要检查什么 → 四维评测。

问题和输入必须在结果前面。官方 fixture 没留下，就写「根据 A/B 摘录重建，不是官方逐字原文」。重建不了的内容直接标缺失，别补故事。

## 四道闸怎么过

`gate_complete` 看问题、输入、Prompt 和 A/B 是否齐。少一块就退回去。

`gate_traceable` 看来源 URL、运行环境、日期和摘录路径能不能追。官方输入缺失不等于不可追，只要重建依据和缺失项写清楚，仍可为 `true`。

`gate_safe` 看客户名、密钥和不该公开的内容是否已经清掉。图像和视频 Prompt 不进这条文字评测线。

`gate_one_pass` 看 A 和 B 是否真的处理过同一输入。A 用裸跑或中性指令，B 加待测 Prompt。四项全是 `true` 才出厂。

## A/B 怎么写

先贴真实摘录，再说差别。完整运行文件缺失时，只能照录现存评测摘录，并明确它不是模型完整输出。不能把摘要补成引语。

差别要落到词句和动作：删了哪句，守住哪条约束，有没有新增数字，结果能不能直接接着做。「更专业」「效果更好」都不算证据。

每页只留一张四维表：结构、约束、胡编、可执行性。模型名没记录就写 `not_recorded`，输入由摘录重建就写 `rebuilt_from_ab_excerpt`。

## 哪些先别出厂

来源追不到、输入说不清、A/B 不是同一任务、摘录被改写、敏感内容没清掉，任意一项出现就停。涉及真实仓库、生产工作流和长期自动化，也要等人批准。
