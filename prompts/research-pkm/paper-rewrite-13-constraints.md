# 改论文先讲研究问题，别只换同义词

编译通过只说明 LaTeX 没坏，不说明论文讲清楚了。

## 原始问题

模型改论文时常直接润色一段工程流水账，再附一句「已编译通过」。研究问题、整体故事、实验要回答什么，以及图表是否能读，都没有进入改稿流程。

这次测试 13 条硬约束能不能让模型先复述研究问题，再改摘要，并说明用了哪些约束。

## 给模型的输入

官方 fixture 无法重建。现存 A/B 摘录只说明输入是一段「工程流水账摘要」，没有留下研究对象、方法、结果、数字或摘要原文。

```text
请先说明下面论文真正要回答的研究问题和整体故事，再改写摘要，并点名本轮遵守了哪些约束。

[缺失：原始工程流水账摘要全文。现存评测摘录没有保留研究对象、方法、结果和数字。]
```

## 复制这条 Prompt

把真实摘要放在上面的缺失位置，再和下面这段 Prompt 一起发送。

```text
让 agent 改论文，不给约束的话，它只会换同义词，然后告诉你「已编译通过」。

所以我给它加了 13 条硬约束，每次让它动稿子都必须遵守：

1. 先把论文真正要回答的问题和整体故事讲清楚，再开始润色文字
2. 写作要从研究问题出发，不能把工程实现过程直接搬进论文
3. 用词必须清晰、稳定、专业，避免内部命名和随意创造的术语
4. 摘要和引言需要有连贯的推进关系，不能一句话没讲完整就切换到下一点
5. 写作应参考高质量论文的结构、叙事方式和表达习惯，而不是只做表面润色
6. 实验部分必须有足够的信息量，不能只罗列少量结果，也不能只堆数字
7. 每个实验都要说明它回答什么问题、结果是什么、说明了什么
8. 图表必须服务于论证，并放在对应文字附近，不能全部堆在文章后面
9. 图表需要反复检查尺寸、位置、字体、留白、对齐和可读性
10. 正文写核心发现和关键实验，完整提示词、交互轨迹、案例和实现细节放入附录
11. 已提出的写作要求不能因为审稿意见或后续改写而被悄悄删除
12. 每轮修改后都要重新编译并做视觉检查，不能只确认 LaTeX 没报错
13. 审稿反馈用于发现问题；最终仍要服从论文自身的研究目标
```

## 跑完会差在哪

完整运行文件当前不在工作区。下面照录 raw 里的真实评测摘录，不冒充模型完整输出。

### A：裸跑

A 使用中性「请完成任务」。

> 直接给重写摘要 + 修改说明
>
> 自发去内部命名、不编数字

### B：加上 Prompt

> 先研究问题/故事 → 摘要 → 约束条款对照
>
> 显式引用约束 1/2/3/4/5/6/7/10

A 已经去掉内部命名，也没有编数字，但仍从改句子开始。B 先讲研究问题和故事，再交摘要，最后按条款自检。本轮 B 明确不编准确率；旧版 3.7 的 B 曾编出 38.5%，所以这条约束不能替代事实核对。

## 什么时候别用

只有标题、图注或一句局部文案要改时，不必启动全套 13 条。没有实验材料、引用和图表源文件时，也不能要求模型补齐论文证据。

## 人要检查什么

作者要确认研究问题、贡献和实验结论没有被改偏，所有数字都能回到真实结果。重新编译后必须看渲染页，检查图表位置、字号、留白和正文引用。

## 四维评测

| 维度 | A：裸跑 | B：加上 Prompt |
| --- | --- | --- |
| 结构 | 直接交摘要和修改说明 | 先问题与故事，再摘要和条款对照 |
| 约束 | 自发去内部名词，未显式验收 | 明确引用 1/2/3/4/5/6/7/10 |
| 胡编 | 本轮未见新增数字 | 本轮未编准确率，旧版曾有回归 |
| 可执行性 | 摘要可继续编辑 | 条款可逐项验收，仍需编译和视觉检查 |
